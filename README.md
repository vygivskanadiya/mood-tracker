## Безпека (практична робота №15)

Аудит клієнтської частини застосунку «Трекер настрою» на три типові проблеми:
XSS через `innerHTML`, зайві чи чутливі дані в localStorage/IndexedDB, роль HTTPS.

### Знайдені проблеми та виправлення

**1. Потенційний XSS у полі `note` (вектор варіанта 3).**
Текст нотатки — єдине вільне текстове поле застосунку, тому саме воно є
найімовірнішим вектором XSS. Перевірку виконано тестовим рядком
`<img src=x onerror="alert('XSS')">`: у навмисно небезпечному варіанті рендеру
(`v-html`) він виконувався як HTML і показував `alert`. Виправлення — рендер
нотатки лише як тексту: у Vue-компоненті `MoodEntry` використовується
інтерполяція `{{ note }}`, а не `v-html`. Після цього той самий рядок
відображається як звичайний текст.

**2. Залишкова копія записів у localStorage.**
Після міграції з localStorage у IndexedDB (практична робота №11) ключ
`moodTrackerEntries` лишався у сховищі разом з усіма текстами нотаток — у
відкритому вигляді й без терміну дії. Записи про настрій є особистими даними,
тому копія видаляється одразу після успішної міграції
(`localStorage.removeItem(STORAGE_KEY)`). У localStorage лишається лише
службовий прапорець `moodTrackerMigratedToIDB`.

**3. Відсутність додаткових рівнів захисту.**
Додано Content-Security-Policy (`<meta>` у `index.html`) і заголовки безпеки
на сервері з практичної роботи №14: `X-Content-Type-Options: nosniff`,
`X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`. CSP забороняє
inline-скрипти та inline-обробники подій, тому блокує `onerror` навіть тоді,
коли небезпечний рядок усе ж потрапив би в розмітку. Директива `'unsafe-eval'`
потрібна лише тому, що Vue підключений через CDN і компілює шаблони в браузері;
зі складанням проєкту її можна прибрати.

### Перевірені місця, які виявилися безпечними

- `apiNotesList.innerHTML = ''` і `app.innerHTML = ''` — присвоєння порожнього
  рядка, дані користувача в розмітку не потрапляють.
- `renderApiNotes()` — картки створюються через `document.createElement()`, а
  текст записується через `textContent`, тому дані з API теж екрануються.
- Решта виводу (`статистика`, `форма`, `сторінка 404`) використовує
  `textContent`.
- Захардкоджених ключів, токенів і паролів у коді немає: з практичної роботи
  №14 застосунок працює з власним локальним API без автентифікації.

### Сховища даних

- **IndexedDB `MoodTrackerDB`** — основне сховище історії: дата, рівень
  настрою (1–5) і текст нотатки. Це навчальний прототип, тому дані
  зберігаються локально без шифрування й без обмеження за часом. У реальному
  застосунку для щоденника настрою варто додати явне видалення історії
  користувачем і не зберігати більше, ніж потрібно.
- **localStorage** — лише прапорець `moodTrackerMigratedToIDB`.

### HTTPS

Застосунок розгортається на GitHub Pages, де HTTPS увімкнено за замовчуванням.
Локальний сервер практичної роботи №14 працює на `http://localhost`, що
допустимо: браузери вважають `localhost` безпечним контекстом. На статичному
хостингу секція «Нотатки спільноти» показує повідомлення про недоступність
записів, бо Node-сервер там не запущено — клієнт обробляє це штатним
`try/catch`.

### Навчальний стенд

`security/xss-demo.html` — окрема сторінка, що показує той самий рядок,
вставлений трьома способами: `innerHTML` без екранування (небезпечно),
`textContent` і `escapeHtml()` + `innerHTML`. Стенд не входить до застосунку й
не працює з реальними даними.
